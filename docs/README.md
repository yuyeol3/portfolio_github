# 저장소 분류 근거

2026-10-14에 Luna 에이전트 3개가 기존 개인 공개 레포 59개를 20·20·19개로 나눠 조사했다. 요청에 따라 외부 팀 공개 레포 `ApptiveDev/Fin-BE`, `ApptiveDev/Fin-API`, `kakaotechcampus-4/ktc4-pusan-4`도 추가로 조사했다. 이 사이트를 위해 새로 만든 `portfolio_github`는 구현 내용을 기준으로 직접 설명했다.

- [조사 1](research-1.md): 개인 레포 20개와 Fin-BE·Fin-API
- [조사 2](research-2.md): 개인 레포 20개와 ktc4-pusan-4
- [조사 3](research-3.md): 개인 레포 19개

각 보고서는 README·재귀 파일 트리·매니페스트·관련 진입점을 확인하고, 빈 저장소·포크·학습 코드·프로토타입·배포 결과물을 구분했다. 모든 소스 줄이나 알고리즘 풀이 전체를 전수 검토한 것은 아니며 소개하는 프로젝트를 빌드·실행하거나 운영 환경을 검증하지 않았다.

## 사이트에 반영한 편집 기준

- 카테고리는 주된 용도로 정한다. AI 에이전트용 스킬은 `ai-tools`, 실제 AI 연동이 없는 세무 화면 Mock은 `web`으로 분류했다.
- 웹 기술로 만든 확장 프로그램·로컬 도구는 사용자 용도가 뚜렷한 `tools`로 분류했다. 문서형 지원 포트폴리오와 발표물은 하나의 카테고리로 모아 메뉴 수를 줄였다.
- 학습 목적으로 구성된 SNS·풀스택 실습은 구현이 있어도 `learning`으로 표시했다.
- 파일이 없는 저장소나 제목만 있는 README는 이름만으로 용도를 확정하지 않고 `other`에 둔다. 임의로 숨기지 않으므로 전체 목록에 계속 표시된다.
- 포크는 API의 Fork 배지로 출처를 드러낸다. 외부 팀 레포에는 참여 배지와 소유자의 전체 경로를 표시한다.
- 프로젝트 관련 소스가 여러 레포로 나뉜 경우에도 목록은 개별 레포 단위로 유지한다. Yacht 통합 저장소 등은 설명에서 역할을 구분했다.
- `ktc4-pusan-4` 역할은 보고서 2의 작성자·병합 상태가 확인된 PR #89·#105·#114·#118의 변경 범위에서 기록했다. Fin 팀 레포는 사용자가 직접 참여 프로젝트로 지정했으며, 원본에 대한 저자별 작업 범위를 따로 확정하지 않아 역할 항목은 비워 두었다.

보고서의 분류는 제안이며 실제 표시 기준은 `content/catalog.json`이다. 서비스 문서와 실제 코드의 시점이 다를 수 있으므로 구현 완성도·운영 상태·성과 수치를 확정해서 소개하지 않는다. 수동 설명과 역할은 개발 진행에 맞춰 갱신해야 한다.
